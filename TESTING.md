# Как проверить новую версию BadgeGenerator

Пошаговая инструкция для тестирования: PySide6 (Qt 6) UI + детекция YuNet +
JSON-конфиги шаблонов + PDF с линиями отреза.

---

## 1. Получить код

Если репозиторий ещё не склонирован:

```bash
git clone https://github.com/krylovam/BadgeGenerator.git
cd BadgeGenerator
git checkout arena/019fc2ae-badgegenerator
```

Если клон уже есть — просто обновиться:

```bash
git fetch origin
git checkout arena/019fc2ae-badgegenerator
git pull
```

## 2. Окружение

Нужен Python 3.9–3.12 (рекомендую 3.10 или 3.11).

**Windows (PowerShell):**

```powershell
python -m venv venv
venv\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**macOS / Linux:**

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Установятся: Pillow, PySide6 (Qt 6), opencv-python (4.x), pytest.

Проверка установки:

```bash
python -c "import cv2, PySide6, PIL; print(cv2.__version__, PySide6.__version__)"
# должно вывести что-то вроде: 4.14.0 6.11.1
```

Убедитесь, что модель детекции на месте (она уже в репозитории):

```
detector/utils/face_detection_yunet_2023mar.onnx   (~230 КБ)
detector/utils/cascade.xml                          (запасной каскад)
```

## 3. Быстрая самопроверка (тесты)

Из корня репозитория:

```bash
python -m pytest tests -q
```

Ожидаемый результат: **44 passed, 1 skipped**. Пропущенный тест —
UI-дымовой (`tests/ui_tests/ui_smoke_test.py`): он пропускается только если
Qt не может инициализироваться (например, на Linux-сервере без графической
библиотеки). На обычном десктопе он должен **пройти**.

## 4. Запуск приложения

Из корня репозитория (обязательно из корня, чтобы работали пути):

```bash
python design/application_controller.py
```

В PyCharm: Run configuration → Script path = `design/application_controller.py`,
Working directory = корень проекта.

## 5. Сценарий ручной проверки

В репозитории уже есть готовые данные для теста:
- фото участников — `tests/assets/photos/` (4 шт.);
- макет бейджа — `tests/assets/1отряд.png`;
- его конфиг — `tests/assets/1отряд.json` (подхватится автоматически).

> ⚠️ Не пересохраняйте конфиг `tests/assets/1отряд.json` через мастер —
> координаты в нём привязаны к тестам. Для экспериментов сделайте **копию**
> макета в отдельную папку (например `my_templates/1отряд.png`) и настраивайте
> копию.

### Шаг 5.1. Главное меню
1. **«Выбрать папку с фото»** → укажите `tests/assets/photos` — появится
   «Фото: найдено 4».
2. **«Выбрать шаблон»** → укажите `tests/assets/1отряд.png` — конфиг найдётся
   сам, справа появится превью макета, в строке статуса — размер бейджа
   (100×70 мм @ 300 dpi).
3. **«Показать пример бейджа с фото»** (под превью) — приложение соберёт
   пример готового бейджа: первое фото из папки + имя/фамилия из названия
   файла. Кнопка переключается на «Показать макет» — вернёт превью макета.
4. **«Быстрая настройка по готовому бейджу…»** — если у вас есть готовый
   бейдж (результат старой версии приложения или образец), выберите его —
   приложение само определит координаты текста и фото по сравнению с макетом
   и создаст JSON-конфиг. Останется только проверить детали в мастере.
5. **«Тип бейджа»** — выберите, для кого бейджи:
   - **Слушатель — 2 поля**: из имени файла берутся первые 2 слова
     (фамилия, имя), остальное (отчество, класс, номер) игнорируется.
     Например: `Петров Пётр Петрович 1 11.jpg` → Пётр / Петров.
   - **Педсостав — 3 поля**: берутся первые 3 слова (фамилия, имя,
     должность). Например: `Иванов Иван Вожатый.png` → Иван / Иванов /
     Вожатый.
   Переключатель сохраняется в конфиг шаблона (в мастере настройки тоже есть
   такой же). Если выбран «Педсостав» — в конфиг добавится поле «Должность».
6. Кнопка **«Настроить шаблон…»** — открыть мастер и вручную расставить
   поля. **Для теста**: скопируйте макет в `my_templates/`, выберите копию,
   откройте мастер, подвиньте мышью поле «Имя» и область фото (уголок области
   тянется), нажмите «Сохранить конфиг» — рядом с копией появится `.json`,
   и макет сразу станет «готовым».
7. Кнопка **«Дальше →»** активируется, когда выбраны и фото, и настроенный
   шаблон.

### Шаг 5.2. Конструктор
1. При переходе пойдёт прогресс-бар «Генерация бейджей…» (детекция лиц YuNet).
2. На бейдже: имя/фамилия сверху, фото вставлено с автоцентрированием по
   глазам.
3. Проверьте управление:
   - стрелки и кнопки ◀▶▲▼ — сдвиг фото;
   - **перетаскивание фото мышью** и **зум колёсиком** прямо на превью;
   - «Отменить (Ctrl+Z)» — откат правок;
   - галочка «Применять правки ко всем бейджам»;
   - поля «Имя»/«Фамилия» — ручное редактирование + «Применить»;
   - «← Назад / Дальше →» — переход по бейджам, счётчик «N из M».
4. **«В главное меню»** — вернуться и донастроить шаблон (например, через
   «Настроить шаблон…»). Правки бейджей будут потеряны — приложение
   предупредит об этом.
5. «Закончить редактирование» → окно сохранения.

### Шаг 5.3. Сохранение
1. В окне сохранения виден **предпросмотр первой страницы PDF** с линиями
   отреза.
2. По умолчанию стоит галочка **«Рисовать линии отреза в PDF»** — снимите и
   поставьте обратно, предпросмотр должен обновляться.
3. Выберите папку сохранения (по умолчанию `ready-badges/`).
4. Нажмите **«Сохранить PDF для печати»** → откройте `badges_list.pdf`:
   - формат A4, бейджи 100×70 мм, **3 штуки на лист** (1 колонка × 3 ряда —
     это честный реальный размер при полях 8 мм);
   - вокруг каждого бейджа — **пунктирная линия отреза**;
   - порядок прямой: первый участник — верхний бейдж.
5. «Сохранить отдельными PNG» — каждый бейдж в отдельный файл
   `<Фамилия>_<Имя>_badge.png`.

### Шаг 5.5. PDF из готовых PNG
Если PNG-файлы бейджей уже есть (сохранены ранее или получены из другого
источника), их можно собрать в PDF-лист для печати:

- **В приложении**: кнопка **«PDF из готовых PNG…»** в окне сохранения →
  выберите несколько PNG → укажите размер бейджа в мм, разрешение и линии
  отреза → «Собрать PDF».
- **Из командной строки**:
  ```bash
  python tools/pngs_to_pdf.py out.pdf badge1.png badge2.png --badge-mm 100x70
  ```
  Полезные флаги: `--dpi 300`, `--no-cut-lines`, `--margin-mm 8`,
  `--gap-mm 3`. Подробности: `python tools/pngs_to_pdf.py --help`.

### Шаг 5.4. Удаление фона (опция)
1. Скопируйте макет в `my_templates/`, выберите его, откройте мастер.
2. Поставьте галочку **«удалять светлый фон с фото»** (секция «Область фото»),
   сохраните конфиг.
3. Сгенерируйте бейджи заново — светлый фон на фото участников станет
   прозрачным (виден только на распечатке; в превью бейджа фон будет белым).

## 5.5. Как пользоваться мастером настройки шаблона

Окно «Настройка шаблона» имеет две вкладки: **«Расстановка элементов»**
и **«Пример бейджа»**. В правой панели вверху — переключатель **«Тип
бейджа»** (Слушатель / Педсостав): он определяет, сколько полей берётся
из имени файла (2 или 3) и добавляет поле «Должность» для педсостава.

### Вкладка «Расстановка элементов»

Логика простая — **три шага**:

1. **Выберите элемент над макетом** (выпадающий список): «Текст: Имя»,
   «Текст: Фамилия» или «Фото область». Подсказка над макетом показывает,
   что делать.
2. **Кликните по макету** — выбранный элемент встанет в точку клика:
   - для текста — его начало (левый верхний угол);
   - для фото — левый верхний угол области.
3. **Кликните по элементу и перетаскивайте мышью** — элемент «схватывается»
   за точку клика и двигается за курсором **без скачков**. У области фото
   есть **синий уголок** в правом нижнем углу — тяните его, чтобы растянуть
   область.

Параметры выбранного элемента меняются в панели **справа**:
- текст: размер шрифта, выравнивание, цвет, «уменьшать шрифт, если не
  влезает» (важно для длинных фамилий);
- **Размер бейджа (для печати)** — измерьте линейкой ваш бейдж и укажите
  ширину/высоту в мм; от этого зависит раскладка в PDF.

Кнопки: «+ поле» — добавить произвольное текстовое поле (например «Отряд»);
«− поле» — удалить; «?» — полная инструкция; «Сохранить конфиг» — записать
JSON рядом с макетом.

### Параметры фото в мастере

Секция «Область фото» (справа) управляет тем, как фото участника
встраивается в бейдж:

| Параметр | Что означает |
|---|---|
| **Позиция X / Y** | Левый верхний угол области фото на макете (в пикселях макета). Меняется автоматически при перетаскивании области мышью. |
| **Ширина / Высота** | Размер области фото на макете. Тянуть за синий уголок — то же самое. Фото вписывается в эту область **без искажения пропорций** (по центру). |
| **Кадр из фото** | **Автоматический.** Размер окна вырезки из исходного фото подбирается так, чтобы его пропорции совпадали с пропорциями области на макете — фото всегда заполняет область без белых полей. Вам не нужно знать размер исходного фото. |
| **Масштаб по лицу** | Насколько крупно лицо в кадре (отношение ширины лица к ширине кадра). **Рекомендации**: 0.3 — «по пояс» (много фона/одежды); **0.4–0.5 — портрет** (голова + плечи, оптимально для бейджа); 0.7–0.8 — крупный план (только голова); **1.0 — только лоб/лицо целиком** (обычно слишком крупно). Подсказка со шкалой видна прямо в мастере под полем. |
| **Смещение лица по Y** | Вертикальное положение лица в кадре: 1.0 — центр лица ровно в центре кадра; **1.1 (по умолчанию) — лицо чуть выше центра**, а снизу остаётся больше места (плечи, одежда); меньше 1.0 — лицо ниже центра. |
| **удалять светлый фон с фото** | Если включено — светлый фон (соединённый с краями кадра) становится прозрачным. В предпросмотре примера бейджа под фото рисуется **шахматная подложка** — так видно, где фон удалён. В финальном PNG прозрачность сохраняется; в PDF при печати прозрачные места становятся белыми. |
| **Порог фона (яркость)** | Пиксели ярче этого значения (0–255) считаются фоном. По умолчанию 225 — подходит для белого/очень светлого фона. **Если фон не удаляется полностью** (например, сероватый или с тенью) — уменьшите порог (210, 200) до тех пор, пока фон не станет прозрачным. Слишком низкий порог может «съесть» светлую одежду. |

> Если лицо не найдено или фото без человека — кадрируется центр фото.

> **Если фото на бейдже получается маленьким**: потяните область фото
> мышью (за уголок), чтобы она стала нужного размера — кадр подгонится
> автоматически, а лицо сохранит размер. Если лицо слишком мелкое/крупное —
> поменяйте «Масштаб по лицу» (больше — лицо крупнее).

### Вкладка «Пример бейджа»

Здесь сразу видно итог: выбираете фото участника (из загруженной папки —
список слева — или любое другое через «Выбрать фото…»), и приложение
показывает, как будет выглядеть бейдж с реальным фото и подписями.
Пример обновляется в реальном времени при изменении полей и фото.
Имя и фамилия в примере берутся из названия выбранного файла.

> Быстрый переход: на вкладке «Расстановка элементов» есть кнопка
> **«Пример бейджа →»** вверху — она сразу открывает вкладку с примером.

> 💡 **Совет**: если вам неудобно расставлять вручную, а есть готовый бейдж
> (пример результата из старой версии приложения) — используйте утилиту
> `tools/derive_config.py` (см. ниже): она сама найдёт координаты текста и
> фото, сравнив макет и готовый бейдж.

### Автоматическое создание конфига по готовому бейджу

```bash
python tools/derive_config.py <макет.png> <готовый_бейдж.png>
```

Готовый бейдж должен быть тем же макетом, но с уже вставленными именем,
фамилией и фото (например, результат старой версии приложения). Утилита
сравнит картинки и создаст `<макет>.json` с координатами текста и фото.
Останется только открыть его в мастере и поправить: порядок полей (верхнее
считается именем), размер шрифта и размер бейджа в мм.

## 7. Если что-то не работает

- Пришлите текст ошибки из консоли (или скриншот).
- Версии пакетов: `pip freeze | findstr /i "pyside6 opencv pillow"` (Windows)
  или `pip freeze | grep -iE "pyside6|opencv|pillow"` (Linux/macOS).
- Проверьте, что запуск идёт из корня репозитория.
- На Linux, если UI-тесты падают с `libGL.so.1`:
  `sudo apt install libgl1 libegl1`.
