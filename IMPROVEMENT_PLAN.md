- Как опция: OpenCV DNN (YuNet) заметно точнее и не сильно дороже; но это не обязательно, если текущая точность устраивает.

## 2. Главное предложение: конфиг шаблона вместо констант

Ввести **JSON-конфиг, лежащий рядом с макетом** (или выбираемый в меню). Все координаты и размеры — в нём; код ничего не знает о конкретном макете.

Пример `template.json` (рядом с `макет.png`):

```json
{
  "template_file": "макет.png",
  "badge_size_mm": [100, 70],
  "dpi": 300,

  "text_fields": [
    {
      "id": "name",
      "label": "Имя",
      "anchor": [240, 520],
      "align": "left",
      "font": "assets/Montserrat.ttf",
      "font_size": 200,
      "color": [0, 0, 0],
      "max_width": 700,
      "auto_shrink": true
    },
    {
      "id": "surname",
      "label": "Фамилия",
      "anchor": [240, 780],
      "align": "left",
      "font": "assets/Montserrat.ttf",
      "font_size": 200,
      "color": [0, 0, 0],
      "max_width": 700,
      "auto_shrink": true
    }
  ],

  "photo": {
    "place_on_badge": [285, 1102, 1290, 1470],
    "crop_from_photo": [0, 0, 1290, 1470],
    "face_scale": 0.5,
    "face_offset_y": 1.1
  }
}
```

Что это даёт:
- Новый макет = положить PNG + JSON в папку, **без правки кода**.
- `BadgeTemplate` (новый класс) читает и валидирует конфиг; `Badge` берёт оттуда все значения.
- Доп. поля (`отряд`, `роль`…) — просто ещё один элемент в `text_fields`; источник значения настраивается (имя файла / имя папки / ручной ввод в UI).

**Промежуточный вариант** (если хочется совсем без JSON): диалог «мастер настройки» — пользователь открывает макет, вводит координаты полей в форме, приложение сохраняет их в JSON. Т.е. JSON — формат хранения, мастер — способ его заполнения без ручного редактирования.

## 3. PDF с линиями отреза

Переписать `images_to_pdf` так:

1. **Реальные размеры.** Размер бейджа в мм берётся из конфига (`badge_size_mm`), печать в 300 dpi. Пропорции бейджа сохраняются всегда (никакого растягивания).
2. **Лист A4** (210×297 мм) с настраиваемыми полями (по умолчанию ~8 мм, т.к. принтеры не печатают в край).
3. **Сетка** — сколько бейджей влезает, считается автоматически из размера бейджа и полей; можно задать желаемое число колонок/строк.
4. **Линии отреза** (реализуются при отрисовке страницы, а не на самом бейдже):
   - пунктирный контур вокруг каждого бейджа,
   - и/или угловые метки (crop marks) — крестики/уголки по углам бейджа, как в типографиях.
   Стиль — параметр функции/чекбокс в UI.
5. **Порядок** — прямой (первый бейдж — левый верхний угол), а не через `pop()`.
6. Мелкие детали: подпись страницы («стр. 1 из N»), предпросмотр страницы в saver, выбор папки сохранения.

Эскиз разметки страницы (вид сверху):

```
┌──────────────────────────────────────┐
│  A4, поля 8 мм                       │
│  ┌────────┐ ┌────────┐ ┌────────┐    │
│  │бейдж 1 │ │бейдж 2 │ │бейдж 3 │    │
│  └────────┘ └────────┘ └────────┘    │   <- пунктир/уголки по контуру
│  ┌────────┐ ┌────────┐ ┌────────┐    │
│  │бейдж 4 │ │бейдж 5 │ │бейдж 6 │    │
│  └────────┘ └────────┘ └────────┘    │
└──────────────────────────────────────┘
```

## 4. UI-улучшения

**Главное меню**
- Превью выбранного макета + кол-во найденных фото (вместо одной строки ошибки).
- Автоопределение JSON-конфига рядом с макетом; если его нет — кнопка «Настроить шаблон».
- Прогресс-бар при загрузке/генерации бейджей (генерация в отдельном потоке `QThread`, чтобы окно не замирало).

**Конструктор (настройка фото на бейдже)**
- Перетаскивание фото мышью (drag), масштаб колёсиком — вместо 6 кнопок.
- Счётчик «N из M», кнопка «применить правки ко всем бейджам», undo/redo.
- Зум относительно центра лица, а не угла фото.
- Редактирование имени/фамилии вручную на случай кривого имени файла.
- Один постоянный `QLabel` + обновление pixmap (без пересоздания виджетов).

**Saver**
- Выбор папки сохранения, прогресс сохранения, предпросмотр первой страницы PDF.
- Чекбокс «нарисовать линии отреза», выбор стиля линий.
